SYSTEM ONE MODEL

大模型还在写小作文，它已经做完 100 次判断了

一个不聊天、不写文章，只给判断和概率的模型。它可能是 Agent 栈里缺的那层，也可能只是一个包装得很好的便宜分类器。

事情是这样的。

上周三，一家在旧金山躲了快两年的公司突然跳出来见人。官网首页第一行大字写着，193.6 倍更快，444.6 倍更便宜。

我盯着这串数字看了好一会儿。

？？？

干 AI 这行久了，对这种带小数点的倍数天然警惕。444.6，连小数点后一位都给你算得明明白白，太像那种把自家跑得最漂亮的一条 workflow 拎出来当封面的套路。结果我往下翻它自己的博客，人在一篇叫 Nuance 的文章里先把自己拆了台，说这俩数字是真实收益的高端区间，还坦白没法证明自己不是在补贴用户。

自己先捅自己一刀。

这反倒让我来了劲。这家公司叫 TypeSafe，那个不聊天的模型叫 Jev。

01

一群最懂 RLHF 的人，为什么开始反对聊天

公司 CEO 叫 Diogo Almeida。这个名字你可能不熟，但他干过的事你一定熟。2022 年那篇 InstructGPT 论文，就是把 GPT-3 调教到会听话、后来直接催生 ChatGPT 的那篇，他在作者名单里排第四。再往前，他 2017 年就在 Google Brain 做研究工程师，后来去了 OpenAI。官方和会议页面现在管他叫「RLHF 和 InstructGPT 的共同发明人」，这话得打个折。RLHF 这个思想本身更早，Christiano 2017 年那波人就做了，InstructGPT 这篇是二十个作者，领衔的是 Ryan Lowe 和 Jan Leike。严谨点说，他是把 RLHF 做成产品级指令跟随的那批核心贡献者之一，不是从 0 到 1 孤胆发明一个东西的人。

可恰恰是这个血统，才解释得通 TypeSafe 今天在干什么。

你想想看，这帮人的手艺是什么。不是从零造 Transformer，而是最懂一件事，怎么用强化学习把模型的输出掰成你想要的形状。他们跟大模型打了这么多年交道，最深的那个伤口是什么，是 RLHF 优化人类偏好带来的副作用。你把模型调得越来越讨好人，它就越来越会「显得对」，而不是「真的对」。谄媚、过度自信、一本正经地胡说八道，这些都是偏好优化的副产品。Almeida 自己对 Forbes 说过一句话，大意是我们一直在为人类优化，而且已经超级擅长讨好人类了。

这话听着有点刺耳，但我觉得他说的是事实。

于是他们反着来了。

既然模型说到底是给软件用的，那就别再为人类的聊天体验优化了，改去为软件的需求优化。软件要的是什么，类型稳定、能按阈值分支、快、便宜、概率能信。这堆需求跟「会聊天」几乎是反着来的。所以他们敢直接放弃文本生成。不是做不到，是故意不做。他们管这叫 Machine Native Intelligence，口号更直白，Build Prod, Not God，去做能上生产的东西，别去当神。

我第一次想明白这个取舍的时候，愣了一下。

这么多年我们看模型，都是比谁更会说人话、谁更像人。结果这拨人扭头去做一个「故意不像人、专门对软件说话」的模型。这个转身，是有因果的，不是拍脑袋选的一个赛道。

说回两个名字，都不是随手起的。

「System One」直接借了卡尼曼《思考，快与慢》。System 1 是快、自动、凭直觉的判断，System 2 是慢、费力、要推理的深思。他们把现在的 LLM 类比成 System 2，把 Jev 摆成 System 1。这是个很聪明的科普框架，但也得说句公道话，真正神经科学里的 System 1 是无意识的直觉，Jev 说到底还是个跑在 GPU 上的判别器，只是比自回归大模型快得多。借个名词，好懂，但别全信。

「Jev」这个名字来自经济学家 William Stanley Jevons，背后是著名的杰文斯悖论。蒸汽机效率越高，煤的需求反而越大。TypeSafe 押的是同一回事，单个判断的成本每降一个数量级，软件里值得做判断的地方就会多一个数量级。

你品品这个叙事。

它根本不是在讲「我做了个更强的模型」，它是在讲「我把判断的边际成本打下来了」。这一下就把公司从模型实验室拉到了基础设施的位置，也顺便解释了它的定价，输入四万美元一万亿 token 这个听着怪，输出 token 直接免费。因为它的输出本来就不是一段要你读的文本，收按 token 计费那一套就不成立了。

02

一个故意不写文章，只负责判断的模型

传统大模型是一个 token 一个 token 往外蹦的，你让它分类，它得先把「好的我来看看……」这一串先写完，再吐出结论，你还得从它的话里把那个结构化结果抠出来。Jev 反着来。你给它一段程序状态，也就是 state，再附上一组带类型的问题，它在一次请求里把所有问题的答案并行算完，直接还给你类型化的结果加概率分布，你代码可以直接 if else 上去，不用解析。

它就三种问题形状。Choice，给几个选项让它选一个，顺手把每个选项的概率也给你。Score，沿着一个有序的等级打分，分数还能落在等级之间。Noul，最简单的是不是问题，直接给你一个 0 到 1 的概率。官方文档里那个样例我印象挺深，一个工单，部门分类给了 billing 0.84、technical 0.159、sales 0.001，再顺手问一句紧不紧急，0.999。你看，这一坨东西代码可以直接拿来路由，不需要再养一个人去读。

训练方法他们起了个新名字，叫 RLCD，校准决策强化学习。跟 RLHF 优化人类偏好、RLVR 优化可程序化验证的奖励都不一样，它优化的是「带认识论诚实概率的校准决策」。翻译成人话，就是训练模型别只会说我选 A，而是学会说我 84 个点选 A，而且这个概率得在一大群问题上整体是准的。

这正是工程师最怕的那个点。

你拿到一个自信满满的答案，却根本不知道该不该信它，这才是最贵的地方。校准概率等于给了你第二根决策轴，高置信的直接自动执行，低置信的丢给人或者丢给推理模型。这个设计的工程直觉，我是认的。

03

193.6 倍更快，然后呢

到这一步，我必须把官方那套话术和真实证据叠在一起，分个等级。做解决方案的人，最容易在这种地方对客说错话。

先看首页那个 193.6 倍和 444.6 倍。这俩数字是官方自己跑的，跑的是它自己定义的 workflow eval，而且参考答案拿的是 GPT-6 Astra 加 Fable 5.1 这俩顶级模型的平均。也就是说，它不光自己出题自己跑，连标准答案都是跟另两个贵模型比谁更像。官方自己都承认这是真实收益的高端，不同渠道的数字还对不上，通稿里写过 100 倍，Vercel 转述又写成 194 倍，脑子一乱都不知道该记哪个。我的判断是，当个上限参考，别拿去对客户做承诺。

再看准确率，这块最有意思。

官方那个 workflow eval 的表里，Jev 的平均准确率其实是 67.8%。你没看错，它不是最准的，GPT-5.6 Sol 是 74.1%，Claude Opus 5 是 73.1%。Jev 真正待的位置，是这张 accuracy 对成本散点图的最左下角，最便宜最快，但准头就是那么个水平。唯一一份中文第三方实测，是硅星人拿 50 条中文电商客服题测的，每道题要连做四项判断全对才算对，Jev 大概 32 条，准确率落在 64 到 65 这个区间，平均 0.73 秒一题，50 题花了差不多两美分，全场最便宜。

同一个实测里，便宜的 DeepSeek V4 Flash 其实比 Jev 还准 1.2 分，只是慢了一截。而美国那几个强模型，Claude Opus 5 干到 86.4%，是真的准，但慢一个数量级，贵 150 到 180 倍。

所以你看出来了吧。这不是谁碾压谁，这是个坐标问题。

然后是那个吹得最响的「零幻觉」。

我得把这个词掰开。官方白纸黑字承认过，它那个 0% 的数字不是实测出来的，是 schema 匹配被数学保证了。准确意思是，它不可能返回你定义之外的选项，也不会给你一段畸形输出。但它会选错啊。67.8% 意味着差不多三分之一的决策，跟那两个强模型的共识是不一样的。把「不会瞎编出 schema 外的东西」说成「零幻觉」，说实话有点语义上的躲闪。它不幻觉的是结构，不是判断。

压轴说校准。这个是它的命根子，也是我最想提醒同行的地方。

官方自己写得很清楚，校准是群体层面的统计性质。它说 0.8，意思是这一类问题里大概 80% 是对的，不是这一条有 80% 的把握就一定对。单条答案它不保证。更关键的是，HN 社区一帮业内人吵了半天，要的就是一条 accuracy 对 automation 的曲线，也就是准确率压在多少的时候，你能放心地自动跑掉百分之多少。官方到现在没给。你自己的数据上它到底校不校准，目前外部没有任何证据。

把这几样叠起来，我的判断是，接口形态这个东西是真的好使，三原语加并行加校准概率，工程团队接起来确实舒服，Vercel 说上线一天就有近 13% 的付费团队用过，社区有人半小时撸了个 jev-chess 出来玩。但能力跃迁这件事，目前更像是在抢一个品类的定义权，而不是一个已经被独立验证过的技术突破。它没有论文，没有参数量，没有公开 benchmark，连个具名的企业客户都还没见着。

04

它不是谁的平替，它在抢四类预算

这事我得一个一个讲，因为它其实没有一个真正一对一的竞品，它是站在四类老方案的交汇点上，抢的是同一个预算。

第一种，传统文本分类器，外加小模型微调。这是过去十年 NLP 工程的默认答案。要工单路由，标个几百条数据，微调一个 BERT 级的小模型，几万块钱跑完，推理几十毫秒，上线稳如老狗。GLiClass 这类标签自由的分类器更省事，不用微调，给几个标签描述就能零样本分类。这是 Jev 最直接的价格和性能对手。刚才那个中文实测里，便宜小模型其实跟它在一个区间。Jev 赌的是你不想自己标数据、自己维护模型，它把标数据加训练加部署这一整套，换成了你写几条 instructions。甜区是快速验证、标签老变的场景。但你要是真有几千条标注数据、场景又稳，那微调出来的小模型长期成本更低，而且那是你的资产，不锁在别人的路线图上。

第二种，现在大家最常用的，frontier 大模型的结构化输出，也就是把 GPT、Claude 调出来给个 JSON schema 让它吐结构，或者让另一个大模型当 judge。优点是通用，随写随用，理解能力天花板高。缺点是慢，秒级到几十秒，贵，每例几分到几毛，而且 JSON mode 只保证格式合法，不保证你判断得对。Jev 打的就是「你为了一个二分类，每次都租一个顶级模型在那儿想 20 秒」这件事。注意，这不是替代关系，是 cascade 关系。高频简单判断走 Jev，低置信或者难题升级给大模型。这也是 Vercel、LangChain 那些工程博客几乎一致推荐的组合。

第三种，专用 reranker。RAG 检索的第二棒，先用向量召回几十篇候选，再用 reranker 逐对打分重排。在纯相关度排序这件垂直的事上，专门的 reranker 又便宜又专精。Jev 自己的 cookbook 都拿它演示过 rerank，但它真正抢的不是 reranker 的饭碗，是 rerank 之后你还想再做一轮业务判断的那个额外环节。它能在同一批并行问题里，既问你这篇相关吗，又问你这篇的结论对客户有利吗，把检索和业务语义捏到一次调用里。

第四种，专用 guardrail，也就是 Llama Guard 这类内容安全分类器，企业合规管线里的老标配。理论上 Jev 那个 yes/no 原语完全能套进去做安全筛查，还能给你置信度做阈值。但两点得拎清楚，它只处理文本、英文为主，也没有任何监管背书。在强合规场景，没人会把合规终判押在一个刚出 stealth、没客户、没公开安全评测的新模型上。它在这儿更适合当 agent 内部的轻量预筛，别拿去当对外的合规闸门。

你看，它没有在任何一类里做到第一。它是比微调小模型省了运维，比 frontier 大模型便宜快两个数量级，比 reranker 多了业务判断，比 guardrail 轻量但少了背书。它干的事，是把一个模糊的判断，从重型推理链里抽出来，变成软件里一个便宜、快、能分支的函数。

顺着这个，我想多聊一句，它今天这个位置，几乎是创始人技术血统直接写出来的。

这帮被「模型太自信地胡说」伤过的人，做出来的产品，命根子就叫校准决策。它的甜区和软肋，其实是同一个取舍生出来的。甜区来自放弃生成，不生成就不会有畸形输出，schema 固定就有类型安全，并行就便宜快。软肋也来自同一个取舍，一旦任务需要解释、需要弃权、需要多步推理、需要精确数字，它设计上就做不了。它官方自己都列了一堆失败模式，计数不可靠，日期比较不行，双重否定会掉点，你别指望它算数，算数交给代码。

所以我常觉得，它不是一个不够好的 LLM，它是一个故意不是 LLM 的东西。你拿评价 LLM 的标尺去量它，结论肯定全错。
05

三个剧本

最可能的那个

它活成 agent 栈里的便宜决策层，成为一层垂直 infra，而不是什么新范式。被 Vercel、Cloudflare、Netlify、LangChain 这些网关和框架集成进去，当 cascade 的第一棒，高频简单判断跑它上面，难题升级给大模型。靠比 LLM 便宜一个数量级这个结构性成本优势活下去，但永远不是市场上最准的那个。网关接入的速度，已经在往这个方向走了。

最危险的那个

是被开源平替加前缀预填这套打法给 commoditize 掉。Sean Goedecke 已经用一个 1.5B 的小模型，花了几个小时复刻出两三倍的加速，社区还冒出来一个 OpenJev，用 Qwen 把同样的接口训了一遍。要是校准这套本事到头来也能靠标准方法在开源小模型上复现，TypeSafe 剩下的差异化就只有托管省心加官方校准，而这在企业里撑不起两亿美金的估值。更要命的是，OpenAI、Anthropic 自己完全可以在现有模型上加个非自回归的判别头，用分发优势直接覆盖掉这个场景，Jev 目前没有论文也没有专利挡得住这条路。

最乐观的那个

是校准真的是真的，Machine Native Intelligence 这个叙事兑现了。要是 RLCD 在真实生产负载上被第三方证明，能给出稳定到敢自动跑的校准概率，那它就不只是个便宜分类器，而是软件终于敢把判断交给模型的那块缺失的地基。这个剧本现在缺两样东西，一份公开的技术报告，和至少一个具名客户在生产环境给你背书。在这之前，它是个很有说服力的 demo 和 API，不是一个已经被证明的品类。

06

如果你做解决方案，现在该怎么用

我知道屏幕前有不少是做解决方案、做 AI 落地的同行。我给的判断很实在。Jev 值得你今天就去 waitlist 里占个位置，挑一个窄、高频、能量化的决策点做个 PoC，比如工单路由、内容打标、LLM 输出校验这种。但你对客的时候，首页那个 193.6 倍千万别拿去说。

真正该做的，是拿你自己的标注数据，画那条 accuracy 对 automation 的曲线，亲眼看看它给的概率在你自己的业务上到底校不校准。这一个数字，比官方所有宣传加起来都重要。对客的时候话别说满，它现在是个 early access 阶段的新东西，价格还是促销价，9 月 25 号就到期，你得把话说成「我们先做个小范围验证」，而不是「我们上了个新范式」。

我有时候觉得，我们这行最缺的从来不是又一个能聊天的模型，而是一个敢说自己只会做判断、不会陪你聊天的东西。TypeSafe 这一步，方向我是认的。只不过方向对，和已经成了，中间还隔着好多份技术报告和客户名单。

大时代啊，朋友们。又一个新物种，刚从 stealth 里探出头来。

我先蹲个坑，慢慢看。
